# 原生工具与研究证据

使用专用工具读取核心运行时有意不解析的格式，包括 PDF、办公文档、电子表格、图像、音频、视频、网页、OCR 和研究数据库。

## 工具边界

1. 按摄入流程将收到的材料原样保存在 `raw/`。
2. 使用合适的工具读取或分析材料，不修改原件。
3. 提取文本、OCR、转换后的 CSV、截图和分析文件默认视为临时工作材料，只有在必须作为长期证据时才持久保存。
4. 由 LLM 判断并编写语义来源卡片或笔记。工具输出只有经过审查并链接到证据后，才能成为 wiki 事实。
5. 当论断需要核查时，在正文中记录相关页码、章节、图、表、时间戳、单元格或行定位信息。

不要仅因为可用工具能够处理某种格式，就向 `wiki.py` 添加解析器、服务、数据库或格式专用依赖。

## 研究判断

处理论文、预印本、报告、书籍、数据集或学术网页时，应区分：

- 作者或材料明确陈述的内容；
- 方法和测量实际支持的结论；
- 局限、无法获取的内容和未解决的问题；
- 用户观点和 LLM 的跨来源解释。

当研究或数据集背景会改变论断含义时，应保留该背景。不得把互相冲突的证据压平为共识，也不得编造无法获得的书目信息。只在信息已知时添加可选标识符或书目属性；即使它们不属于 `index.csv`，运行时仍会保留。

批量处理时，先创建范围明确的来源卡片，再在它们之间建立联系并进行综合。移交给其他研究工作流时，应提供来源页路径、相关笔记、日期、定位信息、分歧和局限，而不是倾倒整个 vault。
